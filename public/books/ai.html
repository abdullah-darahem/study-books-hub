1.1

What Is AI? The Four Approaches

يفكّر ولا يتصرّف؟ زي البني آدم ولا بالمنطق؟

THINK · HUMANThink like humanscognitive modelling: how the human mind works
THINK · RATIONALThink rationally"laws of thought": logic and correct reasoning
ACT · HUMANAct like humansthe Turing Test: can a human tell it is a machine?
ACT · RATIONALAct rationallythe rational agent: do the right thing, achieve the best outcome

This course is about designing rational agents. An agent is an entity that perceives and acts. Abstractly, an agent is a function from percept histories to actions: f : P* → A. For a given class of environments and tasks, we seek the agent with the best performance.

Caveat: computational limitations make perfect rationality unachievable, so we design the best program for the given machine resources.

From the quizzes: AI = making a machine intelligent · its goals: create expert systems and implement human intelligence in machines · the Turing Test checks whether a machine can demonstrate intelligence · expert-system components: knowledge base, inference engine, user interface · a frame = a way of representing knowledge · intelligence = the ability to comprehend and profit from experience.

عالشرح بالعربيجدول ٢×٢ لازم تحفظه
  • الـ AI ليه ٤ تعريفات على محورين: هل الـ AI بيفكّر (think) ولا بيتصرّف (act)؟ وهل بنقيسه على البني آدم (human) ولا على المنطق الصح (rational)؟
  • Think humanly = نقلّد إزاي مخ الإنسان بيشتغل من جوّه (علم نفس وأعصاب).
  • Think rationally = «laws of thought»، يعني المنطق: «كل إنسان بيموت، وسقراط إنسان، يبقى سقراط هيموت».
  • Act humanly = اختبار تورنج: لو بتكلّم حد في شات ومش قادر تعرف هو إنسان ولا آلة، يبقى الآلة نجحت 🤖.
  • Act rationally = ده اللي المادة كلها مبنية عليه: اعمل الصح عشان توصل لأحسن نتيجة. سؤال الامتحان: «Acting rationally focus?» ← Achieving the best outcome.
  • الـ agent = أي حاجة بتحس وبتتصرف. ورياضيًا هو دالة: بتاخد كل اللي شافه لحد دلوقتي (P*) وبتطلّع action (A).
  • ليه مش هنوصل لـ rationality كاملة؟ لأن الكمبيوتر موارده محدودة، فبنعمل أحسن برنامج يقدر عليه الجهاز اللي معانا.

Agents & Environments · The Vacuum World

Sensors و Actuators، والـ agent function والـ agent program

Environmentpercepts →Sensors→Agent ?→Actuatorsactions → back to Environment
  • Agents perceive through sensors and act through actuators (effectors). Agents include humans, robots, softbots, thermostats.
  • Percept = the agent's input at an instant · percept sequence = the complete history of everything the agent has perceived.
  • The agent function maps from percept histories to actions (f : P* → A): it specifies the agent's action in response to every possible percept sequence.
  • The agent program runs on the physical architecture to produce f.

1.3

Rationality, Omniscience & Autonomy

الـ rational مش معناه إنه بيعرف كل حاجة

A fixed performance measure evaluates the environment sequence: it captures the cost or effectiveness of the agent's behaviour, a quantitative measure of how well the agent achieves its goals. Vacuum examples: one point per square cleaned in time T? one point per clean square per time step, minus one per move? penalize for > k dirty squares?

A rational agent chooses whichever action maximizes the expected value of the performance measure, given the percept sequence to date.

Rational ≠Why
Omniscientpercepts may not supply all relevant information. Omniscience = knowledge of the actual outcome of actions
Clairvoyantaction outcomes may not be as expected
Successfulhence rational ≠ successful

Rational ⇒ exploration, learning, autonomy. An autonomous agent can act on its own, without direct human intervention; its behaviour comes from its own experience. A system is autonomous when it has the ability to learn (to compensate for partial or incorrect prior knowledge).

عالشرح بالعربيتعمل أحسن حاجة بالمعلومات اللي عندك
  • الـ performance measure = «الكراسة» اللي بنصحّح بيها الـ agent: بنقيس كفاءة سلوكه وتكلفته بأرقام. مثلًا المكنسة تاخد نقطة لكل أوضة نضيفة، ويتخصم منها نقطة على كل حركة (عشان ماتلفّش على الفاضي).
  • Rational = بيختار الـ action اللي متوقّع يجيب أعلى درجة، بناءً على اللي شافه لحد دلوقتي. الكلمة المهمة «expected»: إحنا بنتكلم عن التوقّع، مش عن النتيجة اللي حصلت فعلًا.
  • Omniscient = بيعرف النتيجة الفعلية لكل action قبل ما يعمله 🔮. ده مستحيل! والـ rational مش omniscient.
  • مثال: إنت بتعدّي الشارع بعد ما بصّيت يمين وشمال، فإنت rational ✅. فجأة وقع عليك تكييف من الدور العاشر 😵. كنت rational بس مش successful، لأنك مش omniscient.
  • Autonomous = بيتصرف لوحده من غير ما بني آدم يمسك إيده، وبيتعلّم من تجربته. سؤال T/F متكرر: «A system is autonomous when it has ability to learn» ← True.
🔮
الطالب الـ omniscient: عارف أسئلة الامتحان قبلهاالطالب الـ rational: فتح المذكرة دي وذاكر الأسئلة المتكررة 😎، وده اللي ممكن يحصل فعلًا
فخ: «Autonomous agents operate independently of any goals and do not require a performance measure» ← False. الـ autonomous لسه ليه أهداف، ولسه بنقيّمه.
فخ تاني: «A performance measure provides a quantitative assessment… but does not capture the quality of decision-making» ← False. هو ده بالظبط اللي بيقيسه.

عالشرح بالعربي٤ أسئلة قبل ما تصمّم أي agent
  • قبل ما تصمّم أي agent اسأل ٤ أسئلة: P = هقيس نجاحه بإيه؟ · E = هيعيش فين؟ · A = هيعمل حاجات بإيه؟ · S = هيحس بإيه؟

  • ⚠️ الـ agent اللي الـ sensors بتاعته مش دقيقة بيبقى في بيئة partially observable، مش «unobservable» (Mid 2026: False). الـ unobservable معناها إن مفيش sensors خالص.
  • Deterministic؟ لو عملت نفس الحاجة في نفس الحالة، هتجيب نفس النتيجة دايمًا؟ الشطرنج: آه. الطاولة (backgammon): لأ، فيه زهر 🎲.

  • Episodic؟ كل قرار لوحده ومالوش علاقة باللي بعده، زي روبوت بيفرز القطع البايظة على سير: كل قطعة مستقلة. أما الشطرنج والتاكسي فـ sequential، لأن كل حركة بتأثّر على اللي بعدها.
  • Static؟ هل الدنيا بتستناك وإنت بتفكّر؟ الكلمات المتقاطعة: آه، static. التاكسي: الشارع بيتحرك وإنت بتفكّر ← dynamic. الشطرنج بساعة: semi (اللوحة ثابتة، بس الوقت بيخصم من سكورك).
  • ⚠️ في الـ static مفيش ضغط وقت. فالجملة «Time pressure is absent is NOT a characteristic of a static environment» ← False، لأن غياب ضغط الوقت هو صفة الـ static فعلًا. (فيها نفي جوّه نفي، ركّز!)
  • Discrete؟ عدد محدود من الحالات (الشطرنج)، ولا مستمر (سرعة العربية واتجاهها)؟ Single-agent؟ حد لوحده (كلمات متقاطعة، تنس ضد الحيطة 🎾)، ولا فيه خصم أو شركاء (شطرنج، تاكسي)؟
  • العالم الحقيقي هو الأصعب في كل حاجة: partially، stochastic، sequential، dynamic، continuous، multi-agent.

1.6

Agent Types: from Reflex to Learning

٤ أنواع بالترتيب + الـ learning agent بمكوّناته الأربعة

Four basic types, in order of increasing generality (all can be turned into learning agents):

1
Simple reflex agent

acts on the current percept only, ignoring the percept history, using condition–action rules (if dirty then suck). Works only if the environment is fully observable.

2
Reflex agent with state (model-based)

keeps an internal state: tracks how the world evolves and what my actions do, so it can handle partial observability. Still chooses by condition–action rules.

3
Goal-based agent

adds goals: asks "what will it be like if I do action A?" and chooses actions by progress toward goal states (search & planning), so it considers future consequences.

4
Utility-based agent

adds utility: "how happy will I be in such a state?" It picks the best of several ways to reach the goal.

🎓 Learning agent: an agent whose behaviour improves over time based on its experience
Performance elementselects external actions (the agent itself)
Criticgives feedback on how the agent is doing, compared with a fixed performance standard
Learning elementmakes improvements; it is what enables the agent to improve its performance over time
Problem generatorsuggests actions that lead to new and informative experiences
عالشرح بالعربيمن الدبّانة للعبقري 🪰➡️🧠
  • ١. Simple reflex = رد فعل على اللحظة الحالية بس، زي ما إيدك بتتشال لوحدها من على الحاجة السخنة 🔥. مفيش ذاكرة خالص. القاعدة اسمها condition–action rule (لو كذا ← اعمل كذا). ولأنه مالوش ذاكرة، مايقدرش يوصل لأحسن تقدير للحالة في بيئة partially observable.
  • ⚠️ «simple reflex agents act based on previous action» ← False: هو بيبص على الـ percept الحالي بس.
  • ٢. Model-based (with state) = عنده ذاكرة أو موديل للعالم: فاكر إيه اللي حصل، وعارف أفعاله بتغيّر إيه. زي المكنسة اللي فاكرة إنها نضّفت B من دقيقتين.
  • ٣. Goal-based = عنده هدف وبيفكّر في المستقبل: «لو عملت كذا هوصل للهدف؟». سؤال الامتحان: «goal-based uses to choose actions» ← progress toward goal states. وده الفرق بين الـ reflex والـ planning agent: الـ reflex بيبص على الحاضر بس، والـ planning بيفكّر في العواقب.
  • ٤. Utility-based = مش بس يوصل، لأ يوصل بأحسن طريقة (أسرع، أرخص، أريح). الـ goal سؤاله «وصلت ولا لأ؟» (آه أو لأ). الـ utility سؤاله «أنا مبسوط قد إيه؟» (درجات).
  • ⚠️ الـ goal-based والـ model-based مش reactive (T/F: False). اللي reactive هو الـ reflex بس.
  • الـ Learning agent، تخيّله طالب بيذاكر:
    • Performance element = إنت وإنت بتحل الامتحان.
    • Critic = المصحّح اللي بيقولك «غلط» 📝.
    • Learning element = إنك تتعلّم من غلطك وتتحسّن ← ده اللي بيخلّي الأداء يتحسّن مع الوقت (جه ٥ مرات!).
    • Problem generator = صاحبك اللي بيقولك «جرّب تحل أسئلة جديدة» ← بيقترح تجارب جديدة.
  • الـ learning-based agents بيتعاملوا مع الـ uncertainty (True)، لأنهم بيتعلّموا من التجربة. ومش محتاجين «fixed, predefined set of rules» (False).

2.1

Problem-Solving Agents & Problem Types

Formulate goal ← formulate problem ← search ← execute

A problem-solving agent is a restricted form of goal-based agent. It works in four steps: formulate goal → formulate problem → search for a solution (a sequence of actions) → execute it.

function SIMPLE-PROBLEM-SOLVING-AGENT(percept) returns an action
  state ← UPDATE-STATE(state, percept)
  if seq is empty then
     goal ← FORMULATE-GOAL(state)
     problem ← FORMULATE-PROBLEM(state, goal)
     seq ← SEARCH(problem)
  action ← RECOMMENDATION(seq, state)
  seq ← REMAINDER(seq, state)
  return action

Romania: on holiday in Arad; the flight leaves tomorrow from Bucharest. Goal: be in Bucharest · states: various cities · actions: drive between cities · solution: a sequence of cities, e.g. Arad, Sibiu, Fagaras, Bucharest.

عالشرح بالعربيإنت شايف ولا مغمّض؟
  • الـ problem-solving agent بيفكّر الأول وبعدين ينفّذ: يحدد الهدف، يكتب المشكلة، يدوّر على سلسلة أفعال توصّله، وبعدين ينفّذها خطوة خطوة.
  • نوع المشكلة بيعتمد على البيئة:
    • Single-state = شايف كل حاجة والدنيا مضمونة، فبتخطط سلسلة أفعال وتمشي عليها. مثال: المكنسة في الأوضة #5 ← [Right, Suck].
    • Conformant = مغمّض خالص ومش عارف إنت فين 🙈. لازم سلسلة تنفع في كل الحالات: [Right, Suck, Left, Suck] هتنضّف الأوضتين أيًّا كان مكانك.
    • Contingency = مش متأكد من النتيجة، بس هتعرف لما تجرّب، فالخطة فيها «لو». مثال: [Right, if dirt then Suck].
    • Exploration = مش عارف حتى الخريطة، فبتستكشف وإنت ماشي، زي أول يوم في كلية جديدة 🏫.
  • «Murphy's law»: أي حاجة ممكن تبوظ هتبوظ 😅. المكنسة ممكن توسّخ الأرض النضيفة وهي بتشفط!

2.2

Problem Formulation: the 4 Items

Initial state · Successor function · Goal test · Path cost

A single-state problem is defined by four items:

1 · Initial statee.g. "at Arad"
2 · Successor function S(x)= set of action–state pairs, e.g. S(Arad) = {⟨Arad → Zerind, Zerind⟩, …}
3 · Goal testexplicit, e.g. x = "at Bucharest", or implicit, e.g. NoDirt(x)
4 · Path costadditive, e.g. sum of distances or number of actions; step cost c(x, a, y) ≥ 0

A solution is a sequence of actions leading from the initial state to a goal state. The solution with the lowest path cost is the optimal solution.

Abstraction: the real world is absurdly complex, so the state space must be abstracted. An abstract state = a set of real states; an abstract action = a complex combination of real actions (e.g. "Arad → Zerind" represents a complex set of routes, detours and rest stops). For guaranteed realizability, any real state "in Arad" must get to some real state "in Zerind". Each abstract action should be "easier" than the original problem.

عالشرح بالعربيأي مشكلة = ٤ حاجات
  • عشان الكمبيوتر يحل مشكلة لازم تقوله ٤ حاجات، زي ما بتقول للـ GPS:
    ١. Initial state: «أنا في عرّاد» 📍. سؤال الكويز: «a problem in a search space is defined by» ← initial state.
    ٢. Successor function: «من هنا أقدر أروح فين، وبأنهي action؟»
    ٣. Goal test: «إمتى أقول وصلت؟». ممكن يبقى صريح (= بوخارست) أو شرط (مفيش تراب).
    ٤. Path cost: «الطريق كلّفني كام؟». بنجمع تكلفة كل خطوة، وكل خطوة تكلفتها صفر أو أكتر (مفيش سالب).
  • الـ solution = سلسلة أفعال من البداية للهدف. وأرخص حل = الحل الأمثل (optimal). سؤال Mid 2024: «relationship between path cost and solution optimality» ← the lowest path cost solution is optimal، مش «الأقصر» ولا «الأسرع».
  • Abstraction = إنك تشيل التفاصيل اللي مالهاش لازمة. لما تقول «سافرت من القاهرة لإسكندرية»، مش هتحكي كل مطب ونَفَس سيجارة في الاستراحة 😅.
  • ⚠️ «NO difference between problem formulation and problem solving» ← False. الـ formulation = إنك تكتب المشكلة، والـ solving = إنك تدوّر على الحل.
  • ⚠️ «Task formulation involves defining goals without considering the environment» ← False. لازم تفهم البيئة الأول.

3.1

Tree Search, States vs Nodes & Evaluation Criteria

الـ fringe، والـ b و d و m، والـ ٤ معايير

Tree search: offline, simulated exploration of the state space by generating successors of already-explored states (expanding states). A strategy is defined by picking the order of node expansion. The fringe holds the generated, not-yet-expanded nodes.

function TREE-SEARCH(problem, fringe) returns a solution, or failure
  fringe ← INSERT(MAKE-NODE(INITIAL-STATE[problem]), fringe)
  loop do
    if fringe is empty then return failure
    node ← REMOVE-FRONT(fringe)
    if GOAL-TEST(problem, STATE(node)) then return node
    fringe ← INSERTALL(EXPAND(node, problem), fringe)
StateNode
a (representation of a) physical configurationa data structure, part of a search tree
no parents, children, depth or path costincludes state, parent, action, depth, path cost g(x)

Multiple nodes can represent the same state (e.g. reaching Arad again by going back). EXPAND creates new nodes, filling the fields and using SUCCESSOR-FN to create the states.

Strategies are evaluated by:

Completenessdoes it always find a solution if one exists?
Time complexitynumber of nodes generated/expanded
Space complexitymaximum number of nodes in memory
Optimalitydoes it always find a least-cost solution?

Measured with: b = maximum branching factor · d = depth of the least-cost solution · m = maximum depth of the state space (may be ∞). Uninformed strategies use only the information available in the problem definition.

عالشرح بالعربيالـ state حاجة، والـ node حاجة تانية
  • الـ search = بنبني شجرة: نبدأ من البداية، و«نوسّع» (expand) أي node يعني نولّد أولاده. والفرق بين أي استراتيجية والتانية هو بنختار أنهي node نوسّعها الأول.
  • الـ fringe = طابور الـ nodes اللي اتولدت ومستنية دورها. لو الطابور فاضي ومالقيناش الهدف ← failure.
  • State vs Node: الـ state = «أنا في عرّاد» (مجرد مكان). الـ node = ورقة في الشجرة فيها: الـ state، مين الأب، الـ action، العمق، والتكلفة g. ولأن ممكن توصل لعرّاد بأكتر من طريق، أكتر من node ممكن يمثّلوا نفس الـ state (T/F: True).
  • المعايير الأربعة: Complete (هيلاقي حل لو موجود؟) · Time (هيولّد كام node؟) · Space (هيشيل كام في الميموري؟) · Optimal (هيلاقي الأرخص؟).
  • b = كل node ليها كام ابن بالكتير · d = عمق أرخص حل · m = أعمق عمق في الشجرة كلها.
  • Uninformed (blind) = مايعرفش أي حاجة غير تعريف المشكلة، يعني مايعرفش الهدف قريب ولا بعيد. ليه بنستخدم استراتيجية منظمة (systematic)؟ عشان نضمن إننا جرّبنا كل الاحتمالات لما نحتاج (Mid 2024).

3.2

BFS, Uniform-Cost & DFS

FIFO ولا LIFO ولا priority queue

Breadth-first search (BFS)

Expand the shallowest unexpanded node. Fringe = FIFO queue (new successors go at the end).

  • Complete? Yes (if b is finite)
  • Time? 1 + b + b² + … + bd + b(bd−1) = O(bd+1)
  • Space? O(bd+1): keeps every node in memory
  • Optimal? Yes if cost = 1 per step; not optimal in general

Space is the big problem: at 100 MB/s, 24 hours = 8640 GB.

Uniform-cost search (UCS)

Expand the least-cost unexpanded node. Fringe = queue ordered by path cost, lowest first. Equivalent to BFS if all step costs are equal.

  • Complete? Yes, if step cost ≥ ε
  • Time? number of nodes with g ≤ C*: O(b⌈C*/ε⌉)
  • Space? O(b⌈C*/ε⌉)
  • Optimal? Yes: nodes expanded in increasing order of g(n)
Depth-first search (DFS)

Expand the deepest unexpanded node. Fringe = LIFO queue (stack): successors go at the front.

  • Complete? No: fails in infinite-depth spaces and spaces with loops (complete in finite spaces if repeated states are avoided)
  • Time? O(bm): terrible if m ≫ d, but may be faster than BFS if solutions are dense
  • Space? O(bm): linear space!
  • Optimal? No
عالشرح بالعربيBFS = بالعرض · DFS = بالعمق
  • BFS = بيمشي دور دور: يخلّص كل الـ nodes اللي في المستوى ده قبل ما ينزل للي بعده. زي طابور البنك: اللي جه الأول يخلص الأول (FIFO) 🏦.
  • مميزات الـ BFS: complete (هيلاقي الحل أكيد لو b محدود)، وoptimal لو كل خطوة بنفس التكلفة. عيبه الكبير: الميموري، لأنه شايل كل الـ nodes. سؤال الامتحان: «time complexity of BFS» ← O(bd+1) زي السلايدز.
  • سؤال متكرر (٤ مرات): «advantage of BFS over DFS» ← الإجابة النموذجية: completeness. (الـ BFS optimal كمان لو التكاليف متساوية، بس الإجابة المعتمدة في الامتحان completeness.)
  • UCS = بيوسّع الأرخص الأول (أقل g). لو كل الخطوات بنفس السعر بيبقى هو هو الـ BFS. ده optimal دايمًا.
  • DFS = بينزل لتحت لآخر الطريق، ولو قفل يرجع (backtrack). زي لما تدوّر على حاجة في درج جوّه درج جوّه درج 🗄️. الـ fringe هنا stack (LIFO): آخر واحد دخل أول واحد يطلع.
  • ميزة الـ DFS الوحيدة الكبيرة: الميموري قليلة جدًا O(bm). سؤال testbank: «requires less memory?» ← DFS. عيوبه: مش complete (ممكن يتوه في طريق مالوش آخر) ومش optimal.
🕳️
DFS في شجرة لا نهائية:«خطوة كمان وأوصل… خطوة كمان… خطوة كمان…» 🐇 ← وده ليه مش complete
3.3

Depth-Limited, Iterative Deepening & Bidirectional

DFS بحد، وبعدين نكبّر الحد، والبحث من الناحيتين

Depth-limited search (DLS)

DFS with depth limit l: nodes at depth l have no successors. Returns solution / failure / cutoff.

  • Complete? Yes, if l ≥ d (otherwise not complete)
  • Time? O(bl) · Space? O(bl)
  • Optimal? No
Iterative deepening search (IDS)

Run DLS with depth 0, 1, 2, … until a solution is found.

  • Complete? Yes
  • Time? (d+1)b⁰ + d b¹ + (d−1)b² + … + bd = O(bd)
  • Space? O(bd)
  • Optimal? Yes, if step cost = 1

b = 10, d = 5: N(IDS) = 123,450 vs N(BFS) = 1,111,100. IDS does better because other nodes at depth d are not expanded. IDS uses only linear space and not much more time than other uninformed algorithms.

Bidirectional search (asked in the midterms)

Search forward from the initial state and backward from the goal simultaneously; a solution is found when the two searches meet in the middle.

  • Time & space: O(bd/2) each; since bd/2 + bd/2 ≪ bd, it is exponentially faster than unidirectional search
  • Needs predecessors (backward successors) to be computable

عالشرح بالعربيIDS = أحسن ما في الـ BFS والـ DFS
  • DLS = DFS بس بحد للعمق، عشان مايتوهش في الشجرة اللا نهائية. المشكلة: لو الحل أعمق من الحد (l < d) مش هيلاقيه. عشان كده سؤال «which is NOT complete?» ← depth-limited search (جه ٤ مرات!).
  • IDS = بنعمل DLS بحد ٠، وبعدين ١، وبعدين ٢… لحد ما نلاقي الحل. شكله بيعيد شغل كتير، بس في الحقيقة معظم الـ nodes في آخر مستوى، فالتكرار مش مكلّف. النتيجة: complete زي BFS + ميموري قليلة زي DFS. ميزته في الامتحان: uses less memory than breadth-first search.
  • Bidirectional = تدوّر من البداية ومن النهاية في نفس الوقت، والحل يظهر لما البحثين يتقابلوا في النص. زي اتنين صحاب ماشيين لبعض من آخر الشارع 🤝. ولأن كل واحد بيمشي نص المسافة: bd/2 بدل bd ← exponentially faster.
  • Branching factor في الـ bidirectional: في أسئلة الامتحان كل state ليها ولدين وأب واحد، فـ forward = 2 وbackward = 1.
  • Graph search = نفس الـ tree search، بس بنكتب الـ states اللي زرناها في قايمة (closed) ومابنرجعلهاش تاني. ده ممكن يوفّر بشكل exponential.

4.1

Best-First & Greedy Search

روح للي شكله أقرب للهدف

Best-first search: use an evaluation function f(n) for each node, an estimate of "desirability", and expand the most desirable unexpanded node. Implementation: the fringe is a queue sorted by desirability, i.e. a priority queue. Special cases: greedy search and A* search.

Greedy search uses the heuristic h(n) = estimate of the cost from n to the closest goal, e.g. hSLD(n) = straight-line distance from n to Bucharest. Greedy search expands the node that appears to be closest to the goal (minimal h(n)).

  • Complete? No: can get stuck in loops, e.g. with Oradea as the goal: Iasi → Neamt → Iasi → Neamt… (complete in finite spaces with repeated-state checking)
  • Time? O(bm), but a good heuristic can give dramatic improvement
  • Space? O(bm): keeps all nodes in memory
  • Optimal? No
عالشرح بالعربيالطمّاع بيبص على الهدف بس
  • Informed = عندنا معلومة زيادة عن المشكلة: «الهدف تقريبًا قد إيه بعيد». المعلومة دي اسمها heuristic h(n). في رومانيا هي المسافة في خط مستقيم (زي الطيارة) من المدينة لبوخارست ✈️.
  • Best-first = بندّي كل node درجة f(n)، ونوسّع صاحب أحسن درجة. عشان كده بنستخدم priority queue (سؤال testbank).
  • Greedy = f(n) = h(n) بس، يعني بيروح للي شكله أقرب للهدف ومش فارق معاه إنه صرف قد إيه لحد هنا. زي واحد شايف البرج من بعيد وماشي ناحيته في خط مستقيم، حتى لو فيه بحر في النص 🌊.
  • عيوبه: مش complete (ممكن يلف في دواير: Iasi ↔ Neamt) ومش optimal. سؤال testbank: «expands nodes with minimal h(n), not optimal» ← greedy best-first search.
🤑
Greedy search: «فاجاراس أقرب لبوخارست في خط مستقيم! يلا!»وصل بتكلفة ٤٥٠ ✅، بس فيه طريق بـ ٤١٨ 🙃 ← مش optimal
4.2

A* Search & Admissible Heuristics

f = g + h: اللي صرفته + اللي فاضل

A*: avoid expanding paths that are already expensive. Evaluation function f(n) = g(n) + h(n):

g(n)cost so far to reach n
h(n)estimated cost from n to the goal
f(n)estimated total cost of the path through n to the goal

A* uses an admissible heuristic: h(n) ≤ h*(n), where h*(n) is the true cost from n (also h(n) ≥ 0, so h(G) = 0 for any goal G). An admissible heuristic never overestimates: e.g. hSLD(n) never overestimates the actual road distance. Theorem: A* search is optimal.

  • Complete? Yes, unless there are infinitely many nodes with f ≤ f(G)
  • Time? exponential in [relative error in h × length of solution]
  • Space? keeps all nodes in memory
  • Optimal? Yes: cannot expand fi+1 until fi is finished. A* expands all nodes with f(n) < C*, some nodes with f(n) = C*, and no nodes with f(n) > C*
عالشرح بالعربيA* = الذكي اللي بيحسب الاتنين
  • الـ A* بيجمع حاجتين: g = صرفت قد إيه لحد هنا + h = فاضل قد إيه تقريبًا. ويختار أقل مجموع f.
  • كأنك بتختار تاكسي: الـ UCS بيبص على العداد بس (g). الـ Greedy بيبص على اللي فاضل بس (h). أما الـ A* فبيبص على العداد + اللي فاضل 🚕، فبياخد أحسن قرار.
  • Admissible = التقدير عمره ما يكون أكبر من الحقيقة (متفائل دايمًا). الخط المستقيم عمره ما هيبقى أطول من الطريق الحقيقي، فهو admissible. ولو الـ h admissible ← A* optimal.
  • عيب الـ A*: بيشيل كل الـ nodes في الميموري.
  • مثال من الخريطة: Arad: f = 0 + 366 = 366. نوسّع: Sibiu 140+253 = 393 · Timisoara 118+329 = 447 · Zerind 75+374 = 449 ← نختار Sibiu، وهكذا لحد ما نوصل لبوخارست بـ 418 عن طريق Rimnicu Vilcea و Pitesti.
⭐
A*: «Bucharest بـ ٤٥٠ ظهرت… بس لسه فيه Pitesti بـ f = ٤١٧ أقل منها»«أستنى أشوفها الأول» 🧐 ← وده سر الـ optimality، لقى ٤١٨
فخ: الـ A* بيقف لما يشيل الهدف من الـ fringe، مش أول ما يولّده. عشان كده Bucharest (450) اتولدت بدري بس ماوقفناش عندها.

عالشرح بالعربياقرا الأرقام صح
  • في الـ A* كل node مكتوب جنبها f = g + h. مثلًا Rimnicu Vilcea: 413 = 220 + 193، يعني صرفنا ٢٢٠ كيلو (140 لـ Sibiu + 80)، وفاضل ١٩٣ في خط مستقيم.
  • Fagaras بتولّد Bucharest بـ 450 = 450 + 0، بس لسه فيه Pitesti بـ 417 أقل، فالـ A* بيوسّعها ويلاقي Bucharest بـ 418.
  • الـ Greedy بيبص على h بس: Sibiu (253) ← Fagaras (176، أقل من Rimnicu 193) ← Bucharest. يعني وصل بسرعة بس بتكلفة 450.

الـ T/F اللي بتتكرر، جاهزة 🪤
  1. Multiple nodes can represent the same state → True
  2. A system is autonomous when it has ability to learn → True
  3. Learning-based agents handle uncertainty → True
  4. Fully observable: sensory input gives all relevant info → True
  5. Agents perceive via actuators → False
  6. Simple reflex acts on the previous action → False
  7. Inaccurate sensors = unobservable → False (partially)
  8. Nondeterministic = entirely unpredictable → False
  9. Goal-based & model-based are reactive → False
  10. Model-free agents rely on explicit environment knowledge → False
  11. Autonomous agents need no goals / performance measure → False
  12. Task formulation ignores the environment → False
  13. No difference between formulation and solving → False
  14. "Time pressure absent" is NOT a static trait → False
  15. Behavioral outcomes = laws of thought → False
  16. Learning agent needs fixed predefined rules → False
  17. Performance measure doesn't capture decision quality → False
