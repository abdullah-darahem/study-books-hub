What an OS actually does

1.1

What Operating Systems Do

الـ OS بيعمل إيه، ويعني إيه Kernel

An operating system is a program that acts as an intermediary between the user and the computer hardware.

OS goals: execute user programs and make solving user problems easier · make the computer system convenient to use · use the hardware in an efficient manner.

A computer system has 4 components: hardware (CPU, memory, I/O) · operating system · application programs · users.

ViewpointThe OS is…
User viewconvenience & ease of use (users don't care about resource utilization) · shared computers must keep all users happy · mobile devices are resource-poor, optimized for usability and battery
System viewa resource allocator (manages all resources, decides between conflicting requests) and a control program (controls execution of programs to prevent errors and improper use)

No universal definition. Good approximation: "everything a vendor ships when you order an OS". The kernel is the one program running at all times on the computer. Everything else is either a system program (ships with the OS but isn't part of the kernel) or an application program.

Today's OSes for general-purpose and mobile computing also include middleware: software frameworks that provide extra services to developers (databases, multimedia, graphics).

عالشرح بالعربيالـ OS = الوسيط بينك وبين الهاردوير
  • تخيّل الهاردوير مطعم، وإنت الزبون. الـ OS هو الجرسون: إنت مش هتدخل المطبخ تطبخ بنفسك، بتطلب منه وهو يتصرّف. ده بالظبط «intermediary between the user and the hardware».
  • الـ computer system ٤ حاجات: Hardware و OS و Application programs و Users. احفظهم بالترتيب ده.
  • من وجهة نظر اليوزر: عايز حاجة سهلة ومريحة ومش فارق معاه الـ CPU مستغل كام في المية. وبتاع الموبايل عايز البطارية تعيش.
  • من وجهة نظر السيستم: الـ OS حاجتين: resource allocator (بيوزّع الـ CPU والميموري والفايلات، ولو اتنين اتخانقوا على حاجة هو اللي يحكم) و control program (بيمنع البرامج إنها تغلط أو تستخدم الجهاز غلط).
  • الـ Kernel = البرنامج الوحيد اللي شغال طول الوقت. أي حاجة تانية يا إما system program يا إما application. السؤال ده جه ٣ مرات.

الـ Kernel وهو شايف كل البرامج بتتقفل وتتفتح:«أنا هنا من أول ما الجهاز فتح… ومش ماشي» 🗿
فخ: «everything below the system-call interface and above the physical hardware» ← دي The Kernel (Mid 2026)، مش system programs.
1.2

Computer-System Organization: Boot & Interrupts

الجهاز بيصحى إزاي، والـ interrupts والـ device drivers

One or more CPUs and device controllers connect through a common bus to shared memory. CPUs and devices execute concurrently, competing for memory cycles.

  • Each device controller is in charge of a particular device type and has a local buffer.
  • Each controller type has an OS device driver to manage it: it provides a uniform interface between the controller and the kernel.
  • The CPU moves data between main memory and the local buffers. I/O is from the device to the controller's local buffer.
  • The controller tells the CPU it has finished by causing an interrupt.

Bootstrap program: loaded at power-up or reboot; stored in ROM or EEPROM (firmware); initializes all aspects of the system, then loads the OS kernel and starts execution.

Interrupts: an interrupt transfers control to the interrupt service routine, generally through the interrupt vector, which contains the addresses of all the service routines. The interrupt architecture must save the address of the interrupted instruction. A trap or exception is a software-generated interrupt caused by an error or a user request. An operating system is interrupt driven.

Handling: the OS preserves the CPU state by storing the registers and the program counter, determines which type of interrupt occurred (polling or vectored interrupt system), and separate code segments determine what to do for each type.

عالشرح بالعربيBootstrap · Interrupt vector · Device driver
  • الـ Bootstrap: أول ما تدوس زرار الباور، الجهاز يكون «فاضي»، مفيش OS في الـ RAM. فيه برنامج صغير متخزن في الـ ROM/EEPROM (اسمه firmware) يصحى الأول، يجهّز كل حاجة ويحمّل الـ kernel. أي سؤال فيه «power-up / reboot / initializes all aspects / first code executed» ← Bootstrap.
  • الـ Device controller: كل جهاز (كيبورد، هارد، طابعة) ليه controller وجوّاه local buffer. البيانات بتروح من الجهاز للـ buffer بتاعه، والـ CPU بينقلها من الـ buffer للميموري.
  • الـ Device driver: برنامج جوّه الـ OS بيكلّم الـ controller. فايدته إنه يدّي الـ kernel طريقة واحدة موحّدة يكلّم بيها أي جهاز. ده «uniform interface» اللي جه ٣ مرات.
  • الـ Interrupt: الـ controller يخلّص شغله فـ «يخبّط» على الـ CPU ويقوله: خلّصت. الـ CPU يسيب اللي في إيده، يحفظ مكانه (registers والـ program counter)، ويروح يشوف المطلوب.
  • يعرف يروح فين إزاي؟ من الـ interrupt vector: جدول فيه عناوين كل الـ service routines. رقم الـ interrupt = رقم الخانة في الجدول.
  • الـ trap/exception = interrupt من السوفتوير: يا إما error (قسمة على صفر مثلًا) يا إما برنامج بيطلب خدمة من الـ OS (system call).
📞
الـ CPU وهو مركّز في شغله:الكيبورد: «interrupt!» · الماوس: «interrupt!» · التايمر: «interrupt!» · الـ CPU: «طب أخلّص السطر ده بس» 😩
احفظها كده: Bootstrap = بيصحّي · Kernel = قاعد على طول · Driver = المترجم مع الأجهزة · Interrupt vector = دفتر العناوين.
1.3

Storage Structure, Caching & I/O

هرم التخزين والـ caching والـ DMA

Main memory (RAM): the only large storage the CPU can access directly; random access; typically volatile (DRAM). Secondary storage: extension of main memory with large nonvolatile capacity: HDD (platters, tracks, sectors) and nonvolatile memory (NVM) devices such as SSDs.

Registers
Cache
Main memory
Nonvolatile memory (SSD)
Hard-disk drives
Optical disk
Magnetic tapes

Storage systems are organized in a hierarchy by speed, cost, volatility.

Caching: copying information into a faster storage system; main memory can be viewed as a cache for secondary storage. Check the cache first; if it's there use it, otherwise copy the data into the cache. Cache is smaller than the storage being cached, so cache management (size, replacement policy) is an important design problem.

DMA (Direct Memory Access): for high-speed I/O devices; the device controller transfers blocks of data from its buffer directly to main memory without CPU intervention. Only one interrupt per block, rather than one per byte.

عالشرح بالعربيكل ما تطلع لفوق: أسرع وأغلى وأصغر
  • الـ RAM هي الحاجة الكبيرة الوحيدة اللي الـ CPU يقدر يكلّمها مباشرة. لكنها volatile: الكهربا تقطع ← كل اللي فيها يطير.
  • الهرم من فوق لتحت: Registers ← Cache ← RAM ← SSD ← HDD ← Optical ← Tape. فوق = زي العربية الفيراري: سريعة وغالية ومكانها ضيق. تحت = زي التريلا: بطيئة بس شايلة كتير ورخيصة.
  • الـ Caching: بتحط نسخة من الحاجة اللي بتستخدمها كتير في مكان أسرع. زي ما بتحط الشاحن جنب السرير بدل ما تقوم تجيبه من الدولاب كل شوية.
  • الـ DMA: بدل ما الـ CPU ينقل البيانات بايت بايت (ويضيّع وقته)، الـ controller ينقل بلوك كامل للميموري لوحده، ويعمل interrupt واحد بس في الآخر.
🛵
من غير DMA:الـ CPU شغال دليفري، بينقل كل بايت لوحده 🥲 · مع DMA: «خد العربية النقل وكلّمني لما توصل» 😎
فخ: الـ DMA بيعمل interrupt لكل block مش لكل byte. ولو قالك «main memory is nonvolatile» ← غلط.
1.4

Computer-System Architecture

بروسيسور واحد ولا كتير؟ Multicore و Clusters

Most older systems used a single general-purpose processor (most systems have special-purpose processors as well).

Multiprocessor systems (parallel / tightly-coupled systems) are growing in use and importance. Advantages: increased throughput · economy of scale · increased reliability (graceful degradation or fault tolerance).

TypeMeaning
Asymmetriceach processor is assigned a specific task
Symmetric (SMP)each processor performs all tasks; each has its own registers & cache, shared memory
Multicoremultiple computing cores on a single chip: faster on-chip communication, less power
NUMAeach CPU has its own local memory, connected by a shared interconnect

Clustered systems: multiple systems working together, usually sharing storage via a storage-area network (SAN); provide a high-availability service that survives failures. Asymmetric clustering: one machine in hot-standby mode. Symmetric clustering: multiple nodes run applications, monitoring each other. Some clusters are for high-performance computing (HPC).

عالشرح بالعربيكذا مخ أحسن من مخ واحد
  • الـ Multiprocessor = أكتر من CPU في نفس الجهاز. مميزاته ٣: throughput أعلى (شغل أكتر في نفس الوقت)، وeconomy of scale (أرخص من كذا جهاز منفصل لأنهم بيشاركوا نفس الميموري والهارد)، وreliability (لو واحد وقع الباقي يكمّل).
  • Asymmetric = كل واحد ليه شغلانة (واحد مدير والباقي بينفّذوا). Symmetric (SMP) = كلهم بيعملوا كل حاجة، وده الأشهر.
  • Multicore = كذا core على نفس الشريحة، فالكلام بينهم أسرع والكهربا أقل.
  • Clustered = كذا جهاز كامل شغالين مع بعض، غالبًا شايلين storage مشترك (SAN). الهدف الأساسي high availability: جهاز يقع والخدمة ماتقفش. في asymmetric فيه جهاز «احتياطي» قاعد مستني (hot-standby).
🧑‍🤝‍🧑
Hot-standby server:قاعد على الدكة طول الماتش مستني حد يتصاب عشان ينزل ⚽
فرّق: Multiprocessor = جهاز واحد فيه كذا CPU · Cluster = كذا جهاز مستقل متوصّلين ببعض.
1.5

OS Operations: Multiprogramming, Time-Sharing & Dual Mode

إزاي الـ OS بيشغّل كذا برنامج، والـ user mode والـ kernel mode

Multiprogramming (batch system): a single user cannot always keep the CPU and I/O devices busy. Multiprogramming organizes jobs (code and data) so the CPU always has one to execute. A subset of jobs is kept in memory; one job is selected via job scheduling; when it has to wait (for I/O, for example), the OS switches to another job. Goal: increase CPU utilization.

Timesharing (multitasking): the CPU switches jobs so frequently that users can interact with each job while it is running → interactive computing. Response time should be < 1 second. Each user has at least one program executing in memory → a process. If several jobs are ready at the same time → CPU scheduling. If processes don't fit in memory, swapping moves them in and out to run. Virtual memory allows execution of processes not completely in memory.

Interrupt driven: hardware interrupts come from devices; software interrupts (trap / exception) come from software errors (e.g. division by zero), requests for OS service (system call), or other process problems (infinite loop, processes modifying each other or the OS).

Dual-mode operation lets the OS protect itself and other system components: user mode and kernel mode. A mode bit provided by hardware distinguishes them (0 = kernel, 1 = user). Some instructions are privileged: executable only in kernel mode. A system call changes the mode to kernel; return from the call resets it to user.

Timer: prevents an infinite loop or a process hogging resources. Set to interrupt the computer after some time period; the OS sets the counter (privileged instruction); when it reaches zero, an interrupt is generated.

عالشرح بالعربيالـ CPU مايقعدش فاضي أبدًا
  • Multiprogramming: برنامج واحد مش هيشغّل الـ CPU طول الوقت، لأنه هيستنى I/O كتير. فالـ OS يحط كذا job في الميموري، وأول ما واحد يستنى يشغّل التاني. الهدف: increase CPU utilization (جه في Mid 2026).
  • ده زي الشيف اللي حاطط الأكلة في الفرن، فبدل ما يقف يتفرج بيقطّع السلطة.
  • Time-sharing: نفس الفكرة بس التبديل سريع جدًا لدرجة إن كل يوزر حاسس إن الجهاز بتاعه لوحده، والـ response time أقل من ثانية. ده نظام interactive. وعكسه الـ batch: non-interactive (Mid 2026).
  • Swapping: الـ processes مش مكفية في الميموري؟ انقل واحدة للهارد مؤقتًا وهات التانية. Virtual memory: تشغّل process مش كلها في الميموري، والجزء الباقي في swap file على الهارد (السؤال ده جه ٤ مرات).
  • Dual mode: الـ OS مش بيثق في برامجك 😂 فيه user mode (البرامج العادية) وkernel mode (الـ OS بس). الـ mode bit: 0 = kernel، 1 = user. أي تعليمة خطيرة (privileged) ماتتنفذش غير في kernel mode.
  • البرنامج عايز حاجة خطيرة (يقرا فايل مثلًا)؟ يعمل system call ← trap ← mode = 0 ← الـ OS ينفّذ ← mode = 1 ويرجع.
  • Timer: عشان لو برنامج دخل infinite loop ماياكلش الجهاز. الـ OS يظبط عدّاد، يخلص ← interrupt ← الـ OS ياخد الكنترول تاني.
🔐
البرنامج: «عايز أكلّم الهارد ديسك مباشرة»الـ OS: «لأ يا حبيبي، اعمل system call زي الناس المحترمة» 🙂
فخ: swapping ≠ virtual memory. Swapping = نقل process كاملة. Virtual memory = تشغيل process مش كلها في الميموري. والـ swap file نفسه = virtual memory.
فخ تاني (Mid 2022): «swapping must never be done with a process that has pending I/O» ← صح. لو نقلتها والـ I/O رجع، هيكتب في ميموري بقت بتاعة process تانية.
1.6

Resource Management & Protection

إدارة الـ processes والميموري والتخزين والـ I/O

A process is a program in execution; a unit of work in the system. A program is a passive entity; a process is an active entity. A process needs resources (CPU, memory, I/O, files, initialization data). A single-threaded process has one program counter specifying the location of the next instruction to execute.

ManagementOS responsibilities
Processcreate & delete user and system processes · suspend & resume · mechanisms for process synchronization, communication, and deadlock handling
Memorykeep track of which parts of memory are in use and by whom · decide which processes (or parts) and data to move in and out · allocate & deallocate memory space
File-systemcreate & delete files and directories · primitives to manipulate them · map files onto secondary storage · backup
Mass-storagemounting/unmounting · free-space management · storage allocation · disk scheduling · partitioning · protection
I/O subsystemhide hardware peculiarities from the user · memory management of I/O: buffering (storing data temporarily while it is being transferred), caching, spooling · general device-driver interface · drivers for specific devices

Protection: any mechanism for controlling access of processes or users to resources defined by the OS. Security: defense of the system against internal and external attacks (denial-of-service, worms, viruses, identity theft). Systems distinguish users by user IDs and group IDs; privilege escalation lets a user change to an effective ID with more rights.

عالشرح بالعربيProgram ≠ Process
  • Program = وصفة الأكل مكتوبة في كتاب: passive، قاعدة على الهارد. Process = إنت وإنت بتطبخها فعلًا: active، شغالة في الميموري.
  • الـ program counter = عنوان التعليمة الجاية (Mid 2026).
  • الـ OS مسؤول عن ٥ إدارات: processes، الميموري، الفايلات، الهارد، والـ I/O. لو السؤال «OS is responsible for…» والاختيارات كلها من دول ← all of the mentioned.
  • الـ Buffer = مكان مؤقت بتستنى فيه البيانات وهي بتتنقل. زي لما الفيديو يعمل buffering: بيحمّل حتة قدام عشان يعرضها من غير تقطيع.
  • Protection = مين مسموح له يوصل لإيه (من جوّه). Security = حماية من الهجوم (فيروسات، DoS).
📖
Program على الهارد: «أنا مجرد نص» 😴بعد ما تدبل كليك: «أنا Process دلوقتي، هاتولي CPU وميموري وفايلات!» 💅
1.7

Virtualization, Kernel Data Structures & Computing Environments

الـ Virtualization وأنواع الأنظمة (Real-time، Network OS…)

Virtualization: allows operating systems to run as applications within other operating systems. Emulation is used when the source CPU type differs from the target type (e.g. PowerPC to Intel x86); generally the slowest method. A VMM (virtual machine manager / hypervisor) provides virtualization services.

Distributed system: a collection of separate, possibly heterogeneous systems networked together (LAN, WAN, MAN, PAN). A network operating system provides features between systems across a network (communication scheme to exchange messages); runs on a server and manages data, users, groups, security, applications.

Kernel data structures (Linux): singly / doubly / circular linked lists · binary search tree (balanced: O(lg n)) · hash map · bitmap.

EnvironmentKey idea
Traditionalstand-alone machines → portals, network computers, firewalls
Mobilehandheld smartphones/tablets: GPS, gyroscope, augmented reality · iOS, Android
Client–serverservers respond to requests generated by clients: compute-server and file-server
Peer-to-peerno distinction between client and server; all nodes are peers (Napster, Gnutella, VoIP/Skype)
Cloudcomputing, storage, apps delivered as a service over a network · SaaS · PaaS · IaaS · public / private / hybrid
Real-time embeddedmost prevalent form of computers · well-defined, fixed time constraints; processing must be done within the constraint

Free and open-source OSes: available in source-code format (GNU/Linux, BSD UNIX incl. core of macOS, Solaris). Counter to the copy protection of proprietary systems such as Microsoft Windows.

عالشرح بالعربيOS جوّه OS 🤯
  • Virtualization = تشغّل OS كأنه برنامج جوّه OS تاني، زي ما بتفتح Linux على VirtualBox وإنت على Windows (Mid 2026). الـ Emulation لما الـ CPU مختلف، وهي الأبطأ.
  • Network OS = شغال على server وبيدير الداتا واليوزرز والجروبات والأمان. زي Windows Server. لو السؤال «runs on a server and manages users, groups» ← Network OS.
  • Distributed OS = أجهزة كتير منفصلة بس شغالة كأنها سيستم واحد. سؤال 2025: «multiple CPUs serve multiple real-time applications and users» ← Distributed.
  • Real-time embedded = الوقت عندهم مقدّس. لازم يخلص في وقت محدد وإلا كارثة: الـ airbag في العربية لو اتأخر نص ثانية ✋. أي سؤال فيه «rigid / fixed time requirements» ← real-time embedded.
  • Linux = open-source (Mid 2022). و Windows = proprietary.
  • الـ Linux kernel بيستخدم: linked lists، trees، hash maps، bitmaps، يعني all of the above.

Services & System Calls

The services an OS provides, how users talk to it (CLI, GUI, touch), how programs talk to it (system calls through an API), how parameters are passed, the six types of system calls, and system programs.

الـ OS بيقدّم إيه من خدمات؟ إنت بتكلّمه إزاي (CLI و GUI)؟ والبرامج بتكلّمه إزاي (system calls)؟ وإيه أنواعها؟

2.1

Operating-System Services

الخدمات اللي الـ OS بيقدّمها لليوزر وللسيستم

OSes provide an environment for execution of programs and services to programs and users.

Services helpful to the user:

  1. User interface: almost all OSes have one: CLI, GUI, touch-screen, batch.
  2. Program execution: load a program into memory, run it, end execution normally or abnormally (indicating error).
  3. I/O operations: a running program may require I/O (file or device).
  4. File-system manipulation: read/write, create/delete, search, list file info, permission management.
  5. Communications: processes exchange information on the same computer or over a network, via shared memory or message passing.
  6. Error detection: the OS must be constantly aware of possible errors in CPU, memory, I/O devices and user programs, and take the appropriate action.

Services for efficient operation of the system itself (resource sharing):

  • Resource allocation: when multiple users or jobs run concurrently, resources must be allocated to each (CPU cycles, main memory, file storage, I/O devices).
  • Logging: keep track of which users use how much and what kinds of resources.
  • Protection & security: protection = all access to system resources is controlled; security = from outsiders, requires user authentication, defends external I/O devices from invalid access.
عالشرح بالعربي٦ خدمات ليك + ٣ للسيستم
  • احفظ خدمات اليوزر بالاختصار U-P-I-F-C-E: User interface · Program execution · I/O · File system · Communications · Error detection. قولها «أبي فيس» 😅
  • Program execution: يحمّل البرنامج ويشغّله ويقفله، سواء normally أو abnormally. سؤال «cascading termination» إجابته الاتنين.
  • Communications: طريقتين: shared memory (حتة ميموري مشتركة) أو message passing (رسايل عن طريق الـ OS).
  • Error detection: الـ OS بيراقب الأخطاء في الـ CPU والميموري والأجهزة والبرامج، فسؤال «errors handled by the OS» ← all of the mentioned.
  • خدمات السيستم: Resource allocation (يوزّع)، Logging (يسجّل مين استخدم إيه)، Protection & security.
  • لما process تقع، الـ OS بيكتب معلومات الخطأ في log file (Mid 2023). والـ core dump = صورة ميموري الـ process وقت ما وقعت.

2.2

User & OS Interface: CLI, GUI, Touch

إنت بتكلّم الـ OS إزاي

CLI (command interpreter) allows direct command entry. Sometimes implemented in the kernel, sometimes by a systems program. Sometimes multiple flavors exist: shells (e.g. Bourne shell, C shell, bash). It fetches a command from the user and executes it. Commands are either built-in, or just names of programs (adding new features doesn't require modifying the shell).

GUI: a user-friendly desktop metaphor interface: mouse, keyboard, monitor; icons represent files, programs, actions; invented at Xerox PARC. Many systems include both CLI and GUI (Windows = GUI + CLI "command" shell; macOS = "Aqua" GUI + UNIX kernel and shells; Unix/Linux = CLI + optional GUI such as KDE, GNOME).

Touchscreen interfaces: no mouse; actions and selection by gestures; virtual keyboard for text entry; voice commands.

عالشرح بالعربيشاشة سودا ولا أيقونات؟
  • CLI = الشاشة السودا اللي بتكتب فيها أوامر. البرنامج اللي بيفهم الأوامر اسمه command interpreter أو shell (bash مثلًا).
  • الأوامر نوعين: built-in جوّه الـ shell نفسه، أو اسم برنامج منفصل. ميزة النوع التاني إنك تزوّد أوامر جديدة من غير ما تعدّل الـ shell.
  • GUI = سطح المكتب والأيقونات والماوس. اتخترع في Xerox PARC، مش Apple ولا Microsoft 😏.
  • Touch = gestures وكيبورد افتراضي وأوامر صوتية.

2.3

System Calls, API & Parameter Passing

البرنامج بيطلب خدمة من الـ OS إزاي

System calls: the programming interface to the services provided by the OS. Typically written in a high-level language (C or C++). Mostly accessed by programs via a high-level API rather than direct system-call use. Three most common APIs: Win32 API (Windows), POSIX API (UNIX, Linux, macOS), and the Java API (JVM).

Example: even copying one file to another needs a sequence of system calls: acquire input file name, write prompt, accept input, open input file, create output file, read, write (loop), close, write completion message, terminate normally.

Implementation: a number is associated with each system call; the system-call interface maintains a table indexed by these numbers. It invokes the intended system call in the kernel and returns the status and any return values. The caller needs to know nothing about how the system call is implemented: just obey the API. Most details are hidden by the API, managed by the run-time support library.

Parameter passing (3 methods):

  1. Pass the parameters in registers (simplest; but there may be more parameters than registers).
  2. Store the parameters in a block (table) in memory, and pass the address of the block as a parameter in a register (Linux & Solaris).
  3. The program pushes the parameters onto the stack, and the OS pops them off.

Block and stack methods do not limit the number or length of parameters.

  • البرنامج مش مسموح له يلمس الهاردوير (فاكر الـ dual mode؟). فلو عايز يقرا فايل أو يطبع، لازم يطلب من الـ OS. الطلب ده اسمه system call. زي شبّاك الخدمة في المصلحة الحكومية: تقدّم الطلب وتستنى 😂

  • المبرمج غالبًا مابيكلّمش الـ system call مباشرة، بيستخدم API: مكتبة جاهزة. أشهرهم: Win32 (ويندوز)، POSIX (Linux و Mac)، Java API.
  • كل system call ليه رقم، والـ system-call interface عنده جدول بالأرقام دي. والحلو إن المبرمج مش محتاج يعرف هي متنفذة إزاي.
  • تمرير الـ parameters ٣ طرق: Registers (أسهل بس عددها محدود) · Block في الميموري وتبعت عنوانه في register · Stack (push/pop). آخر طريقتين مالهمش حد للعدد.

2.5

System Programs

البرامج اللي جاية مع الـ OS

System programs provide a convenient environment for program development and execution. Most users' view of the OS is defined by system programs, not the actual system calls.

  • File management: create, delete, copy, rename, print, dump, list files & directories.
  • Status information: date, time, available memory, disk space, number of users · performance, logging, debugging · some systems implement a registry to store and retrieve configuration information.
  • File modification: text editors · commands to search file contents or perform transformations.
  • Programming-language support: compilers, assemblers, debuggers, interpreters.
  • Program loading & execution: absolute loaders, relocatable loaders, linkage editors, overlay loaders, debugging systems.
  • Communications: virtual connections among processes, users and systems: messages, web browsing, email, remote login, file transfer.
  • Background services: launch at boot time; some run until shutdown. Provide disk checking, process scheduling, error logging, printing. Run in user context, not kernel context; known as services, subsystems, daemons.
  • Application programs: don't pertain to the system; run by users; not typically part of the OS.
عالشرح بالعربياللي إنت شايفه من الـ OS
  • إنت عمرك ما شفت system call بعينك. اللي بتشوفه system programs: الـ File Explorer، الـ Task Manager، الـ Terminal… فـ نظرة اليوزر للـ OS = الـ system programs.
  • أنواعها: إدارة الفايلات · معلومات الحالة (وفيها الـ Registry في ويندوز) · تعديل الفايلات (editors) · دعم البرمجة (compilers و debuggers) · تحميل وتشغيل البرامج (loaders) · الاتصالات · background services.
  • الـ daemons = برامج شغالة في الخلفية من أول الـ boot، زي اللي بيدير الطباعة. بيشتغلوا في user context مش kernel.

  • OS = intermediary between user & hardware
  • System = hardware · OS · apps · users
  • System view: resource allocator + control program

Boot · interrupts · storage
  • Bootstrap in ROM/EEPROM → loads kernel
  • Interrupt → save regs + PC → vector → routine
  • Trap = software interrupt (error or syscall)
  • Registers › cache › RAM › SSD › HDD › optical › tape
  • DMA: block → memory, one interrupt per block
Running many things
  • Multiprogramming → CPU always busy · batch
  • Time-sharing → interactive · < 1 s
  • Swapping (whole process) vs virtual memory (partly in RAM)
  • Mode bit 0 kernel · 1 user · privileged = kernel only
  • Timer stops infinite loops
  • Multiprocessor: throughput · economy · reliability

  • System: resource allocation · logging · protection & security

  • Interface to OS services · used via API (Win32 · POSIX · Java)
  • Numbered · table in syscall interface

قايمة الفخاخ 🪤
  1. Bootstrap runs at all times → No, the kernel does.
  2. Device controller gives the uniform interface → No, the driver does.
  3. DMA interrupts once per byte → No, once per block.
  4. Main memory is nonvolatile → No.
  5. Batch is interactive → No, time-sharing is.
  6. Mode bit 1 = kernel → No, 0 = kernel.
  7. Swapping is OK with pending I/O → Never.
  8. printf() is a system call → No, it calls write().
  9. chmod() is file management → No, protection.
  10. GUI was invented by Apple → No, Xerox PARC.
